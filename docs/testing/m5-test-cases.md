# Milestone 5: end-to-end and integration test cases

These are the scenarios run against the full stack, with what each one expects and the result
of the latest run. Each Actual Result is what the test asserted on that run.

- **Source of results:** CI run
  [43998998097](https://github.com/cse416-fa26-sixseven/bug-bounty-marketplace/actions/runs/43998998097)
  (PR #148 final head, 2026-11-17).
  - E2E: the `e2e-chain` job ran 10 tests, 10 passed (`junit-e2e-chain` artifact).
  - Chain-mode integration: the `containers` job ran 15 tests, 15 passed (`junit-system-tests`
    artifact).
- **Stack (E2E):** `stack:demo`: a local anvil chain (chain id 31337) with fresh contracts, the API
  in chain mode, the analysis worker and the PoC sandbox, with 60-second challenge and refund
  windows.
- **Stack (integration):** `stack:ci` plus the chain-mode `api-chain` service on port 3002, on
  anvil with the default windows. There is no sandbox, so no PoC verdicts in this tier.
- Nothing touches Sepolia.
- **Roles:** the E2E specs drive the web app in Chromium, with an anvil test wallet for each role
  (developer, auditor, arbiter). The integration tests call the API over HTTP and sign with viem.

Summary results, per-tier counts and the bugs these tests found are in [m5-results.md](m5-results.md).

## Scenarios not covered by an automated test

- **Logout revocation (M5-4):** a copied session cookie stays valid until it expires (8 h). This
  is a known limitation, not tested.
- **Dispute lapse:** the arbiter misses the ruling window. The lapser is unit-tested, but no
  E2E covers it.
- **Claim expiry after 10 minutes, and resuming a claim from the profile.** Unit-tested only.
- **Sepolia and MetaMask (injected wallet).** Checked by hand on prod; CI uses anvil keys.
